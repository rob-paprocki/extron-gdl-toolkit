# Extron `.gdl` — format and programmatic authoring

Notes from reverse-engineering Extron GUI Designer **1.27.0.9** project files,
verified end to end: machine-written `.gdl` files open in GUI Designer, survive
structural edits, and **build successfully**.

Everything here was derived from the files in `fixtures/gdl/`, GUI Designer's own
snapshot renders, and the installed assemblies. Nothing came from Extron
documentation, so treat version 1.27.0.9 as the tested boundary.

---

## 1. Container

A `.gdl` is a **ZIP whose 4-byte record signatures read `KP` instead of `PK`**
(local header, central directory, EOCD, data descriptor). Swap those two bytes
back and any standard ZIP tool opens it. Two members:

| Member | What it is |
|---|---|
| `ProjectGCP` | .NET `BinaryFormatter` graph of `Extron.GUICPro.PBProject`. **This is what GUI Designer opens and edits.** The embedded font binaries live here too. |
| `<project_name>.tgz4` | A plain ZIP (despite the name) holding the *built* panel payload: `layout.json` + `N.png`. Regenerated by Build; the panel runs from this. |

Editing only `ProjectGCP` is enough. The payload goes stale and GUI Designer
rebuilds it.

## 2. What Build actually does

Measured by diffing a project before and after a build:

1. **Rasterises** every control and every button state to a PNG sized to the
   control's exact rect, and writes them as `N.png`.
2. **Deduplicates by appearance.** One asset backs many controls (a single
   asset served 24 controls in the test project). **Text is not part of the
   raster** — two labels with different captions were assigned the *same*
   asset. Captions are drawn live by the panel firmware from `layout.json`.
3. **Assigns `TLPImageID`.** Authored controls carry `-1`; Build fills them in.
4. **Regenerates `layout.json`** from the authoring model.
5. **Auto-creates popup page references for every modal popup on every page.**
   A page authored with none came back with one per modal popup. Do not author
   these — the app manages them.
6. Bumps `VersionInfo` (one increment per save/build), updates `RevisionDate`,
   sets `BuildStatus=Done`, and renames the payload member to the file name
   lowercased with underscores.

The practical consequence: **an authoring tool never makes artwork.** It sets
semantic properties (border, fill, icon, corner radius) and Build makes pixels.

## 3. Reading and writing `ProjectGCP`

Use **32-bit Windows PowerShell 5.1** —
`C:\Windows\SysWOW64\WindowsPowerShell\v1.0\powershell.exe`. Two reasons:
.NET Framework still has `BinaryFormatter` (removed in modern .NET), and
Extron's assemblies are x86, so a 64-bit host fails with "incorrect format".

Preload every DLL plus `GUI Designer.exe` from
`C:\Program Files (x86)\Extron\GUI Designer` into a hashtable and serve them
from an `AssemblyResolve` handler. Calling `LoadFrom` *inside* the handler
recurses until the stack overflows.

Re-serialising an untouched project in memory is byte-identical. An
open-then-save round trip through a *file* is not: it differs by a few thousand
bytes, because deserialisation materialises lazily-built state that then gets
written back. Use the in-memory comparison as the regression test, and compare
semantics (page/popup/control counts and fields) rather than bytes across a
save.

`GdlProject.ps1` wraps all of this.

## 4. Clone, never construct

`PBPage(PBProject)`, `PBPopupPage(...)` and friends throw
`NullReferenceException` headless — they reach for `FormMain`, the toolbox
service and the undo engine. Property setters fail the same way, and are worse
than useless because they **write the backing field first and then throw while
notifying**, so a failed set looks like it worked.

Instead: deep-clone an existing object through `BinaryFormatter` and write its
backing fields by reflection.

This works because `ParentProject`, `Site`, `DesignView` and `PBSystem` are
`[NonSerialized]` — the stored graph is a pure data tree with no upward links,
so a page clones standalone (~107 KB, not the whole multi-MB project).
Collections are plain `List<T>` with ordinary `Add`/`Remove`.

Backing fields worth knowing:

| Field | On | Notes |
|---|---|---|
| `idField` | `PBControlBase` | UInt64, editor handle, unique **within its page** |
| `userIdField` | `PBControlBase` | UInt16 — this is the **ID** Extron shows and the control program addresses |
| `nameField`, `textField` | | |
| `leftField` `topField` `widthField` `heightField` | `PBDrawObject` | |
| `modalField`, `groupIDField`, `groupNameField` | `PBPopupPage` | |
| `popupReferencesField`, `hasReferencesField` | `PBPopupPage` | back-pointers |
| `popupIDField`, `groupIDField` | `PBPopupPageID` | on the reference control |
| `popupPageGroupsField` | `PBProject` | the group registry |

## 5. Modal vs standard popups

A clean split, and it drives everything about references:

| | Modal | Standard |
|---|---|---|
| Size | full screen | sub-page |
| Group | always ungrouped (0) | in a group, in every referenced case |
| Placement | invoked directly; references auto-created by Build | placed by a popup page reference bound to its **group** |

Cloning a modal popup as the target of a hand-authored reference is a dead end.

## 6. Popup bindings live in four places

Every one of these must agree. **Each mismatch fails silently** — the file
opens and builds, the binding just reads "Unassigned" in the UI:

1. the reference control's `PopupPageID` (`popupIDField` / `groupIDField`)
2. the popup's `groupIDField` **and** `groupNameField`
3. the popup's `popupReferencesField` — a `List<PBPopupReference>` of
   `{projectIDField, pageIDField, popupPageIDField, objectIDField,
   objectTypeField}` back-pointers — plus `hasReferencesField`
4. `PBProject.popupPageGroupsField`, the group registry: a
   `List<PBControlGroup>` of `{nameField, idField, referenceCountField}`.
   **An unregistered group id renders as "Unassigned."**

A generator should assert all four agree rather than trusting the writes.

## 7. Gotchas

- PowerShell **unrolls a single-element list** returned from a function. Use
  `return ,$x`, or a `List<T>` reads back as a bare element and misleads you.
- `$HOME` and `$PID` are reserved PowerShell variables.
- `referenceCountField` semantics are still unknown: stored 46 / 8 / 13 / 2
  against member counts 11 / 1 / 2 / 2. Setting it to a plausible number caused
  no visible problem.
- Cloned controls keep the source's `UserId` and per-page `ID`. Duplicate IDs
  are legal (Extron uses them for feedback mirrors) but allocate fresh ones
  unless a mirror is what you want.
